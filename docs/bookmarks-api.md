# 음성 북마크 API

노트의 중요한 시점을 서버에 저장한다. 녹음 중 남긴 북마크와 재생 중 추가한 북마크는 같은 API를 사용한다. MongoDB의 `voice_note_bookmarks` 컬렉션에 노트 ID와 북마크 ID를 결합한 키로 저장하며, 전사 문서는 수정하지 않는다. 전사·화자 편집이나 요약 재생성이 북마크를 덮어쓰지 않는다.

| API | 동작 |
| --- | --- |
| `GET /api/notes/{noteId}/bookmarks` | 재생 시간순 북마크 배열 |
| `PUT /api/notes/{noteId}/bookmarks/{id}` | 북마크 생성 또는 수정; 같은 ID 재시도는 중복을 만들지 않음 |
| `DELETE /api/notes/{noteId}/bookmarks/{id}` | 해당 노트의 북마크 삭제; 이미 없으면 그대로 완료 |

`id`는 클라이언트가 생성하는 UUID다. PUT 본문은 다음 형식이다.

```json
{"positionMs": 12500, "label": "출시일 결정"}
```

시간은 녹음 시작 후 경과 시간(0~24시간)이며 일시정지 시간은 제외한다. 이름은 앞뒤 공백을 제외한 1~80자이고 줄바꿈·제어 문자는 허용하지 않는다. 이름을 생략하면 기본값은 `중요한 순간`이다. 노트당 최대 200개이며, 새 ID를 추가하는 경우에만 한도를 확인한다.

노트가 존재해야 한다. 잘못된 입력은 400, MongoDB 장애는 설명이 포함된 502를 반환한다. 화면은 저장 실패한 북마크를 브라우저 세션에 보관하고 사용자가 재시도하면 같은 ID로 PUT한다. 녹음 자체가 업로드되기 전에 남긴 북마크는 메모리에 있으므로, 그 시점에 페이지를 닫으면 녹음과 함께 사라진다.

기존 노트 권한 모델과 동일하게 개인용 또는 접근이 제한된 서버를 전제로 한다. MongoDB의 문서 저장·시간순 복원·노트별 키·중복 없는 재시도·오류 처리는 `BookmarkServiceTest`에서 검증한다.
